## 4. กติกาที่ใช้ทุก Checkpoint

### 4.1 วงจรการทำงาน

```text
ทาย → แก้ → รัน → สังเกต → อธิบาย → ผ่าน
```

**ขั้นตอน "ทาย" ห้ามข้าม** — ก่อนแก้โค้ดทุกครั้ง เขียนคำทำนายลงในใบงานก่อนว่าคิดว่าจะเกิดอะไรขึ้น การทายผิดแล้วรู้ว่าผิด สร้างความเข้าใจได้มากกว่าการทำถูกโดยไม่รู้ว่าทำไม

### 4.2 หลังจบทุก CP ให้ทำ 5 อย่าง

1. รันแอปแล้วทดสอบด้วยตาตัวเอง
2. รัน `npm run check -- --session=1`
3. กรอกผลลงใน `TEST_REPORT.md` **แม้ผลจะเป็น FAIL ก็ต้องบันทึก**
4. ตอบคำถามประจำ checkpoint ให้ได้ด้วยประโยคเดียว
5. `commit` ด้วยข้อความที่สื่อความหมาย

### 4.3 อ่านผล checker ให้เป็น

```bash
npm run check -- --session=1
```

| สัญลักษณ์ | ความหมาย |
|---|---|
| `[PASS]` | ผ่านแล้ว |
| `[TODO]` | ยังไม่ผ่าน — เป็นงานของคาบนี้ |
| `[SKIP]` | **งานของคาบ 5B ยังไม่ต้องทำ** |

เริ่มต้นคุณจะได้ประมาณ **92/104** และเมื่อจบคาบต้องได้ **104/104**

> **สำคัญ** — checker ตรวจโครงสร้างและพฤติกรรมของ Service เท่านั้น **ตัวเลขเต็มไม่ได้แปลว่าแอปใช้งานได้ถูกต้อง** คุณยังต้องเปิดเบราว์เซอร์ทดสอบด้วยตาเอง

### 4.4 ติดแล้วทำอย่างไร

ลองตามลำดับนี้ก่อนถาม แต่ละขั้นให้เวลาตัวเองไม่เกิน 3 นาที

| ขั้น | ทำอะไร |
|---|---|
| 1 | อ่านข้อความ error ให้จบทั้งบรรทัด แล้วถามตัวเองว่ามันบอกไฟล์ไหน บรรทัดไหน |
| 2 | เปิด DevTools → Console ดูว่ามี error อื่นซ่อนอยู่ไหม |
| 3 | เปิดเอกสารประกอบการสอน 5A บทที่เกี่ยวข้อง (ดูตารางในหัวข้อ 10) |
| 4 | อธิบายปัญหาให้เพื่อนข้าง ๆ ฟังเป็นคำพูด — บ่อยครั้งจะเจอคำตอบตอนกำลังอธิบาย |
| 5 | **ยกมือ** |

> **ติดที่จุดเดิมเกิน 10 นาที ให้ข้ามไปขั้นที่ 5 ทันที** ไม่ใช่เรื่องน่าอาย และเรามีทางลงเตรียมไว้ให้แล้ว

### 4.5 การใช้ AI

ใช้ได้สำหรับอธิบาย error หรือเปรียบเทียบทางเลือก **แต่ต้องบันทึกใน `AI_USAGE.md`** และต้องอธิบายโค้ดของตัวเองได้ทุกบรรทัด ทุก checkpoint มีคำถามที่ต้องตอบด้วยปากเปล่า

## 7. CP02 — ประกอบเส้นทางทั้ง 5 เส้น

**เวลา 45 นาที · ทำพร้อมกัน 1 เส้นทาง จากนั้นทำเองอีก 4 เส้นทาง**
**TODO ที่เกี่ยวข้อง:** `5A-CP02` ใน 3 ไฟล์

### ทายก่อนแก้

> ถ้าเราเปลี่ยน `children` เป็น `<Outlet />` แต่ยังไม่ได้ประกอบเส้นทาง จะเกิดอะไรขึ้น

### เส้นทางที่ต้องได้

| `path` ในโค้ด | URL ที่ผู้ใช้เห็น | หน้า |
|---|---|---|
| `index` | `#/` | DashboardPage |
| `requests/new` | `#/requests/new` | NewRequestPage |
| `requests/:requestId` | `#/requests/REQ-001` | RequestDetailPage |
| `about` | `#/about` | AboutPage |
| `*` | อะไรก็ตามที่เหลือ | NotFoundPage |

### ทำ

1. `AppLayout.jsx` — เปลี่ยน `children` เป็น `<Outlet />` แล้วเอา prop `children` ออก
2. `App.jsx` — ประกอบ `<Routes>` โดยให้ `AppLayout` เป็นกรอบครอบทุกเส้นทาง
3. `AppHeader.jsx` — เพิ่ม `<nav>` ที่มี `NavLink` 3 ปุ่ม

### สามเรื่องที่ต้องระวัง

**หนึ่ง — `path` ไม่ต้องใส่ `#`**
Router เติมให้เอง ถ้าเราใส่เข้าไปด้วยจะกลายเป็นการหาเส้นทางชื่อ `#/about` ซึ่งไม่มีอยู่

**สอง — ปุ่ม Dashboard ต้องใส่ `end`**
`NavLink` ที่ `to="/"` ถ้าไม่ใส่ prop `end` จะขึ้นสถานะ active ในทุกหน้า เพราะทุกเส้นทางขึ้นต้นด้วย `/`

**สาม — สถานะ active ต้องสื่อได้มากกว่าสี**
คนตาบอดสีต้องดูออกด้วย ให้เพิ่ม `aria-current` หรือทำให้รูปลักษณ์ต่างอย่างชัดเจน ไม่ใช่แค่เปลี่ยนสี

### ผ่านเมื่อ

- เปิดได้ครบทั้ง 5 URL และ refresh ที่ทุก URL แล้วยังได้หน้าเดิม
- กดเปลี่ยนหน้าแล้ว DevTools → Network **ไม่มีไฟล์ `.html` ใหม่**
- สถานะ active ทำงานถูกต้อง

### คำถามที่ต้องตอบได้

> **`<Outlet />` ทำหน้าที่อะไร**

### ปัญหาที่พบบ่อย

| อาการ | น่าจะเป็นเพราะ |
|---|---|
| **ทุกหน้าว่างเปล่า** แต่ header กับ footer ขึ้น | ลืมใส่ `<Outlet />` — อาการที่พบบ่อยที่สุดของ CP นี้ |
| `#/about` ไปโผล่ NotFoundPage | ใส่ `#` ใน `path` |
| ปุ่ม Dashboard active ตลอดทุกหน้า | ลืม prop `end` |
| `#/unknown` ไม่ขึ้น NotFoundPage | เส้นทาง `*` อยู่นอกกรอบ `AppLayout` |
| เปลี่ยนหน้าแล้วจอกะพริบ | ใช้ `<a href>` แทน `<Link>` หรือ `<NavLink>` |

`fetch()` ไม่โยน error เมื่อเซิร์ฟเวอร์ตอบ 404 มันถือว่าติดต่อสำเร็จ เพียงแต่ได้หน้า error กลับมา ถ้าไม่ตรวจแล้วเรียก `.json()` ต่อ คุณจะได้ error แปลก ๆ ว่าแปลง HTML เป็น JSON ไม่ได้ ซึ่งไม่บอกเลยว่าปัญหาจริงคือหาไฟล์ไม่เจอ

**สอง — ต้องใส่เครื่องหมายคำถามใน `import.meta.env?.BASE_URL`**
ถ้าไม่ใส่ checker จะเรียกฟังก์ชันนี้นอก Vite ไม่ได้ แล้วจะไม่ผ่านทั้งที่โค้ดทำงานปกติในเบราว์เซอร์

**ทดสอบก่อนไปต่อ** — ใน `DashboardPage` ใส่ `console.log` ชั่วคราวเพื่อดูว่าเรียก Service แล้วได้ข้อมูล 3 รายการจริง

### CP03-2 · state และ Effect เฉพาะกรณีสำเร็จ (25 นาที)

**ทายก่อนเขียน**

> dependency array ของ Effect นี้ควรมีอะไรบ้าง และถ้าใส่ `requests` เข้าไปด้วยจะเกิดอะไรขึ้น

state ที่ต้องมี

```text
loadState      idle | loading | success | error
requests       รายการคำร้อง
statusFilter   ตัวกรอง
errorMessage   ข้อความเมื่อพลาด
```

**ทำเฉพาะกรณีสำเร็จก่อน** ยังไม่ต้องมี loading หรือ error

> **ถ้าหน้าจอค้างหรือ Console ขึ้นข้อความรัว ๆ** ให้เช็ค dependency array เป็นอย่างแรก อาการนี้เกิดจากการใส่ค่าที่ Effect ตัวนั้นเป็นคนเซ็ตเอง ลงไปใน dependency array

**สิ่งที่ต้องคำนวณตอนวาดหน้าจอ ไม่ใช่เก็บใส่ state**

`summary` และ `filteredRequests` คำนวณได้จาก `requests` กับ `statusFilter` ที่มีอยู่แล้ว **อย่าเก็บซ้ำใน state** เพราะจะทำให้มีข้อมูล 2 ชุดที่ต้องคอยทำให้ตรงกัน วันไหนลืมจะได้หน้าจอที่แสดงผิดโดยไม่มี error ให้จับ

### CP03-3 · เพิ่ม loading / error / empty (15 นาที)

ใช้ `LoadingState` และ `ErrorState` ที่ starter เตรียมไว้ให้ ส่วนสถานะไม่มีข้อมูลต้องเขียนเอง และต้องมี `data-testid="empty-state"`

**เงื่อนไขที่ต้องระวังที่สุด**

สถานะไม่มีข้อมูลต้องตรวจ **สองเงื่อนไขพร้อมกัน**

```text
โหลดสำเร็จแล้ว   และ   ไม่มีรายการ
```

ถ้าตรวจแค่จำนวนรายการเป็นศูนย์ ผู้ใช้จะเห็นข้อความ "ยังไม่มีคำร้อง" แวบหนึ่งทุกครั้งที่เปิดหน้า เพราะตอนเริ่มต้นรายการยังว่างอยู่จริง ๆ

**ทดสอบด้วย URL พิเศษ**

| URL | ควรเห็น |
|---|---|
| `#/` | โหลดแล้วขึ้นรายการ |
| `#/?scenario=error` | ข้อความผิดพลาด + ปุ่มลองใหม่ |
| `#/?scenario=empty` | ข้อความว่ายังไม่มีคำร้อง |

หน้าจอต้องมีป้ายบอกด้วยว่ากำลังอยู่ในโหมดทดสอบ ไม่ใช่ทำให้ผู้ใช้เข้าใจผิดว่าระบบพังจริง

### CP03-4 · ปุ่มลองใหม่ (10 นาที)

ปุ่มลองใหม่ต้องรับมือ 2 กรณี

| กรณี | ต้องทำ |
|---|---|
| อยู่ใน `?scenario=error` | **ลบ scenario ออกจาก URL ก่อน** แล้วโหลดใหม่ |
| ไม่มี scenario | สั่งให้ Effect ทำงานอีกรอบ |

กรณีแรกใช้ `useSearchParams()` ส่วนกรณีที่สองใช้ `useManualReload` ที่ starter ให้มาแล้ว

```js
import useManualReload from '../hooks/useManualReload.js';

const [reloadKey, reload] = useManualReload();

useEffect(() => {
  // โหลดข้อมูล
}, [scenario, reloadKey]);
```

> ถ้ากดลองใหม่แล้วยังอยู่ที่ `?scenario=error` มันก็จะพลาดซ้ำไปเรื่อย ๆ ไม่จบ
